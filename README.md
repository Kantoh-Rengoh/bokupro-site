# ESY 選手成長予測（ぼくのプロ野球 成長記録サイト）

セーブデータ（.tfosave）を GitHub に置くだけで、自チームの選手成長予測サイトが自動で更新されます。

- 公開ページ： https://kantoh-rengoh.github.io/bokupro-site/
- リポジトリ： https://github.com/Kantoh-Rengoh/bokupro-site

---

## 毎回の更新手順（iPhoneだけで完結します）

### 1. ゲームからセーブデータを「ファイル」アプリに保存する

ゲーム内の書き出し機能で `.tfosave` ファイルを iPhone の「ファイル」アプリに保存します。
ファイル名は日本語や記号が入っていても大丈夫です。

### 2. GitHub の saves フォルダにアップロードする

1. iPhone の Safari で https://github.com/Kantoh-Rengoh/bokupro-site/tree/main/saves を開く
   - ログイン画面が出たら GitHub にログインする
2. 右上の「**…**」（点が3つのボタン）→「**Upload files**」を押す
   - パソコンの画面では「**Add file**」→「**Upload files**」です
   - どちらも見当たらないときは、アドレスバー左の「ぁあ」→「**デスクトップ用Webサイトを表示**」に切り替える
3. 「**choose your files**」を押し、「ファイル」アプリから保存した `.tfosave` を選ぶ
4. ファイル名が画面に出たら、下の緑の「**Commit changes**」を押す

### 3. 数分待ってサイトを開き直す

アップロード後、GitHub が自動で計算して公開ページを更新します。目安は 3〜5 分です。
サイトを開いたときに前の内容が出る場合は、ページを下に引っ張って再読み込みしてください。
見出しの下の「ゲーム内の日付」が新しくなっていれば更新完了です。

### うまくいかないとき

- **アップロードが「25MB まで」と拒否された**：ブラウザからのアップロードは 1 ファイル 25MB までです。セーブデータは通常 15〜17MB なので収まりますが、超えた場合はパソコンの GitHub Desktop などから送る必要があります。その場合は Claude Code に相談してください。
- **数分待っても更新されない**：リポジトリの「**Actions**」タブを開くと、直近の実行が並びます。赤い ✕ がついていたら失敗です。その行を押し、「解析・予測を実行」を開くと、日本語で原因が書いてあります。そのメッセージをそのまま Claude Code に貼ってください。
- **古いセーブデータは自動で `saves/archive/` に移動**します。手で消す必要はありません。

## 「オフの編成提案」タブについて

セーブデータをアップロードすると、成長予測と一緒に「オフの編成提案」も自動で作られます（`docs/data/roster_plan.json`）。
ページ上部のタブで切り替えます。

| 一覧 | 条件（しきい値は `scripts/roster_plan.py` の冒頭で変えられます） |
| --- | --- |
| 1. 支配下 → 育成 | 支配下・外国人以外でプロ2年目。ドラフト1位で総合80以上・20歳以下は「残留（例外）」。予測最大70以下は 2 の一覧へ |
| 2. 支配下 → 自由契約 | 25歳以上で伸びしろ2以下のうち、総合82未満／開幕時の総合が2年連続で低下（総合85以下）／下降期で総合85以下 → 推奨。それ以外で総合82〜84 → 検討。外国人は印付き |
| 3. 育成 → 支配下 | 総合82以上 → 即昇格。予測最大90以上かつ総合75以上 → 先行昇格 |
| 4. 育成 → 自由契約 | 予測最大70以下。例外リスト（ID指定）は「残留（検証中）」 |
| 5. 育成契約満了 | 昇格条件を満たせば「支配下」。予測最大70以下、または24歳以上で伸びしろ2以下かつ予測最大80未満なら「自由契約」。それ以外は「育成再契約」 |
| 6. ドラフト候補 | 中卒・高卒で将来性A。他球団の関心数・1位候補にしている球団数を併記。1位指名の推奨と、抽選に外れた場合の次点を表示 |

- 同じ選手が複数の一覧に当てはまるときは、番号の小さい一覧に出ます。契約満了の選手は 5 だけに出ます。
- 「予測最大」はこのタブでは**今後の見込み**です。設定ピーク年齢を過ぎた選手は過去の最高値を含めないので、成長予測タブより低くなることがあります（伸びしろ＝予測最大−総合）。
- 一覧の上の表は、提案をすべて実行した場合の人数です。「ドラフトの指名人数」に数字を入れると「ドラフト後」の列が変わります。
- 判定は、同じ条件でも予測の誤差（在籍選手 ±3、ドラフト候補 ±4〜5）で境界の選手が入れ替わることがあります。予測最大が 69〜71 の選手は特に注意してください。

### 例外リスト（育成で残す選手）を変えたいとき

`scripts/roster_plan.py` の `D2F_KEEP_IDS` に、選手の `id` と名前を書きます（`id` は `docs/players.json` に載っています）。
Claude Code に「◯◯を例外リストに入れて」と頼めば書き換えてもらえます。

## 質問ボックスに質問を追加したいとき

`docs/qa.json` に同じ形式で 1 件追加します（自動更新では上書きされません）。
`本文` の書き方は次の 3 種類です。

- `|列1|列2|列3` … 「|」で始まる行は表になります（最初の行が見出し）
- `- 文章` … 「- 」で始まる行は箇条書きになります
- それ以外の行 … ふつうの段落になります

質問と回答の文章を Claude Code に渡して追記してもらうこともできます。

## 仕組み（興味のある人向け）

```
bokupro-site/
├ saves/                  … セーブデータを置く場所（古いものは archive/ へ自動移動）
├ scripts/build.py        … セーブデータの展開・総合の推定・成長予測・三軍推奨・JSON出力
├ scripts/roster_plan.py  … オフの編成提案（しきい値はこのファイルの冒頭）
├ docs/                   … 公開されるサイト本体
│   ├ index.html / css / js
│   ├ players.json        … build.py が自動生成（手で編集しない）
│   ├ meta.json           … ゲーム内日付などの更新情報（自動生成）
│   ├ data/roster_plan.json … オフの編成提案（自動生成）
│   └ qa.json             … 質問ボックス（手で追記する）
├ .github/workflows/build.yml … アップロードをきっかけに build.py を動かす設定
├ requirements.txt        … Python の部品一覧
└ README.md
```

1. `saves/` に `.tfosave` が追加されると GitHub Actions が起動する
2. GitHub 上の仮想マシンで Python と部品を入れ、`scripts/build.py` を実行する
3. `docs/players.json`・`docs/meta.json`・`docs/data/roster_plan.json` が書き換わり、自動でコミットされる
4. GitHub Pages（公開元は `docs` フォルダ）が再公開される

### build.py の計算内容

| 項目 | 方法 |
| --- | --- |
| セーブ時点の総合 | 役割ごとに、過去の「能力6項目→総合」の組から重みを最適化し、単調変換（等張回帰）で合わせる |
| 予測最大・到達年齢 | 引退選手と34歳以上の選手の経歴から勾配ブースティング回帰で学習。新人は専用モデル |
| 状態 | 新人／下降期／ピーク／成熟期／伸び盛り（到達年齢と設定ピーク年齢から判定） |
| 前年比 | 今の値 − 直近の開幕時の値 |
| 三軍推奨 | 一軍以外・24歳以下・伸びしろ5以上から、新人→伸びしろ10以上→その他の順に「全選手数−70」人 |
| 練習メニュー | 役割ごとの総合への重み × (100 − 能力値) が最大の能力 |
| 今後の最高（編成提案用） | 「その年以降の最高総合」を目的変数にした勾配ブースティング。設定ピーク年齢を過ぎた選手にだけ使う |
| ドラフト候補の予測最大 | 引退選手＋31歳以上の在籍選手で学習（1年目開幕時の総合・年齢・将来性・注目度・投手か・developmentPotential・riseRate・peakAge・growthVolatility）。候補の1年目開幕時の総合は今の総合＋2 |

### パソコンで手動実行したいとき

```
pip install -r requirements.txt
python scripts/build.py
```

`saves/` 内の一番新しい `.tfosave` を自動で選びます。
