# ESY 選手成長予測（ぼくのプロ野球 成長記録サイト）

セーブデータ（.tfosave）を GitHub に置くだけで、自チームの選手成長予測サイトが自動で更新されます。

- 公開ページ： https://kantoh-rengoh.github.io/bokupro-site/
- リポジトリ： https://github.com/Kantoh-Rengoh/bokupro-site

---

## 毎回の更新手順（iPhoneだけで完結します）

### 1. ゲームからセーブデータを「ファイル」アプリに保存する

ゲーム内の書き出し機能で `.tfosave` ファイルを iPhone の「ファイル」アプリに保存します。
ファイル名は日本語や記号が入っていても大丈夫です。

### 2. GitHub の saves フォルダにアップロードする

1. iPhone の Safari で https://github.com/Kantoh-Rengoh/bokupro-site/tree/main/saves を開く
   - ログイン画面が出たら GitHub にログインする
2. 右上の「**…**」（点が3つのボタン）→「**Upload files**」を押す
   - パソコンの画面では「**Add file**」→「**Upload files**」です
   - どちらも見当たらないときは、アドレスバー左の「ぁあ」→「**デスクトップ用Webサイトを表示**」に切り替える
3. 「**choose your files**」を押し、「ファイル」アプリから保存した `.tfosave` を選ぶ
4. ファイル名が画面に出たら、下の緑の「**Commit changes**」を押す

### 3. 数分待ってサイトを開き直す

アップロード後、GitHub が自動で計算して公開ページを更新します。目安は 3〜5 分です。
サイトを開いたときに前の内容が出る場合は、ページを下に引っ張って再読み込みしてください。
見出しの下の「ゲーム内の日付」が新しくなっていれば更新完了です。

### うまくいかないとき

- **アップロードが「25MB まで」と拒否された**：ブラウザからのアップロードは 1 ファイル 25MB までです。セーブデータは通常 15〜17MB なので収まりますが、超えた場合はパソコンの GitHub Desktop などから送る必要があります。その場合は Claude Code に相談してください。
- **数分待っても更新されない**：リポジトリの「**Actions**」タブを開くと、直近の実行が並びます。赤い ✕ がついていたら失敗です。その行を押し、「解析・予測を実行」を開くと、日本語で原因が書いてあります。そのメッセージをそのまま Claude Code に貼ってください。
- **古いセーブデータは自動で `saves/archive/` に移動**します。手で消す必要はありません。
- **saves フォルダの外（リポジトリの一番上）にアップロードしてしまった**ときも、自動で `saves/` に移して処理します。同じ名前のファイルがあるときは `A_2.tfosave` のように番号が付きます。
- アップロードのたびにリポジトリは約 17MB 大きくなります（GitHub の目安は 1GB）。年に数回なら問題ありませんが、頻繁に上げる場合は Claude Code に履歴の整理を相談してください。

## 「オフの編成提案」タブについて

セーブデータをアップロードすると、成長予測と一緒に「オフの編成提案」も自動で作られます（`docs/data/roster_plan.json`）。
ページ上部の「編成提案」タブで切り替えます。

**考え方**：ドラフト後に **支配下 68人・育成 80人** になるように、戦力外（自由契約）の人数を決めます。
「ドラフトの指名人数」に支配下・育成の指名人数を入れると、その分だけ戦力外の人数が増えます（入力した数字はその端末に保存されます）。

**戦力外の候補と優先順位**（しきい値は `scripts/roster_plan.py` の冒頭で変えられます）

1. 25歳以上で総合80未満
2. 24歳で総合75未満
3. 23歳で総合70未満
4. 上のどれでもないが、予測最大が80未満

- どの段階でも、**予測最大が80以上（総合80以上の見込みあり）の選手は候補にしません**。
- 同じ段階の中では、予測最大の低い順（同じなら総合の低い順）に選びます。
- 候補が足りないとき（残りが全員「80以上の見込みあり」）は、その旨を表示して人数は目標より多いままになります。

| 一覧 | 中身 |
| --- | --- |
| 1. 支配下 → 育成 | 支配下・外国人以外でプロ2年目。ドラフト1位で総合80以上・20歳以下は「残留（例外）」 |
| 2. 支配下 → 自由契約 | 支配下の戦力外（上の優先順位で、必要な人数だけ）。次点も5人まで表示。育成へ移す2年目の選手が戦力外に入った場合もここに出ます |
| 3. 育成 → 支配下 | 総合82以上 → 即昇格。予測最大90以上かつ総合75以上 → 先行昇格 |
| 4. 育成 → 自由契約 | 育成の戦力外のうち、契約満了ではない選手。例外リスト（ID指定）は「残留（検証中）」 |
| 5. 育成契約満了 | 昇格条件を満たせば「支配下」、戦力外の人数に入れば「自由契約」、それ以外は「育成再契約」 |
| 6. ドラフト候補 | 高卒で将来性A。他球団の関心数・1位候補にしている球団数を併記。1位指名の推奨と、抽選に外れた場合の次点を表示 |

- 「予測最大」は**今後の見込み**です。設定ピーク年齢を過ぎた選手は過去の最高値を含めません（成長予測タブと同じ値です）。
- 予測最大が 78〜79 の候補には「境界」の印が付きます。予測の誤差（±3）で候補から外れることがあるので、戦力外にする前にゲーム画面で確認してください。

## 三軍推奨の基準

一軍以外の選手から、次の順に「全選手数 − 70」人まで選びます（`scripts/build.py` の冒頭 `THIRD_SQUAD_...` で変えられます）。

1. 年齢ごとの総合の基準を満たす選手：20歳で55以上／21歳で60以上／22歳で65以上／23歳で70以上／24歳で75以上／25歳で80以上
2. 1 は満たさないが、総合80に届く見込みがある選手（今の総合が80未満で、予測最大が80以上）
3. それでも三軍に空きがあれば、20歳以下の選手を総合の高い順

- 1 と 2 だけで枠を超えるときは、1 → 2 の順に予測最大の高い選手から入れます。
- 選手の詳細を開くと「三軍推奨」の札の隣に理由（年齢基準／80到達の見込み／空き枠）が出ます。

## 「ドラフト候補」タブについて

日本一決定戦の後〜ドラフト前のセーブデータ（`draft.stage` が `scheduled`）のときだけ、高卒の候補全員と3つの枠を表示します（`docs/draft.json`）。
ドラフト後や開幕前のセーブデータでは「今はドラフト候補の時期ではありません」と出ます。

| 枠 | 中身 |
| --- | --- |
| 1位候補 | 予測最大の高い順。興味を持つ球団が多いほど抽選になりやすい（「抽選 高／中／低」で表示） |
| 狙い目 | 興味を持つ球団が1以下で予測最大が高い順（2位以降で取れる見込み） |
| 育成候補 | スカウト順位100位以下だが予測最大75以上 |

- 候補の行をタップすると、能力5項目・成長タイプ・到達年齢・誤差・興味球団数・1位候補にしている球団数・自チームの補強方針との一致・スカウトのメモが開きます。
- 絞り込み（ポジション・将来性・注目度）と並べ替え（予測最大・スカウト順位・興味球団数・総合）、名前検索が使えます。
- 予測は1年目開幕時の総合（今の総合＋2.3）から出した参考値で、誤差は平均±4〜5です。
- 人数やしきい値は `scripts/roster_plan.py` の冒頭（`DRAFT_TOP_N` など）で変えられます。

## 二刀流の選手・注目度

- 二刀流の選手（セーブデータに `twoWay` 欄がある選手）は、投手側と野手側を別々に計算します。一覧では「二刀流」の札が付き、ポジションは両方を表示します。一覧の総合はゲームの表示に合わせた合成値（高い側×0.75＋低い側×0.25。2162年のデータで確認）、予測最大・伸びしろは高い側の値です。詳細を開くと「投手として」「野手として」の2段で、それぞれの能力だけで計算した総合・予測・前年比が見られます（過去の実績が少ないため「参考値」）。
  - 二刀流の選手の `abilityHistory` に記録されている総合も合成値なので、前年比や予測はその年の能力値から片側の総合を出し直して比べています。
- 将来性の隣に注目度（ドラフト時の `attentionGrade`）を表示します。外部入団などで記録がない選手は「—」です。

### 例外リスト（育成で残す選手）を変えたいとき

`scripts/roster_plan.py` の `D2F_KEEP_IDS` に、選手の `id` と名前を書きます（`id` は `docs/players.json` に載っています）。
Claude Code に「◯◯を例外リストに入れて」と頼めば書き換えてもらえます。

## 質問ボックスに質問を追加したいとき

`docs/qa.json` に同じ形式で 1 件追加します（自動更新では上書きされません）。
`本文` の書き方は次の 3 種類です。

- `|列1|列2|列3` … 「|」で始まる行は表になります（最初の行が見出し）
- `- 文章` … 「- 」で始まる行は箇条書きになります
- それ以外の行 … ふつうの段落になります

質問と回答の文章を Claude Code に渡して追記してもらうこともできます。

## 仕組み（興味のある人向け）

```
bokupro-site/
├ saves/                  … セーブデータを置く場所（古いものは archive/ へ自動移動）
├ scripts/build.py        … セーブデータの展開・総合の推定・成長予測・三軍推奨・JSON出力
├ scripts/roster_plan.py  … オフの編成提案（しきい値はこのファイルの冒頭）
├ docs/                   … 公開されるサイト本体
│   ├ index.html / css / js
│   ├ players.json        … build.py が自動生成（手で編集しない）
│   ├ meta.json           … ゲーム内日付などの更新情報（自動生成）
│   ├ data/roster_plan.json … オフの編成提案（自動生成）
│   ├ draft.json           … ドラフト候補（自動生成）
│   └ qa.json             … 質問ボックス（手で追記する）
├ .github/workflows/build.yml … アップロードをきっかけに build.py を動かす設定
├ requirements.txt        … Python の部品一覧
└ README.md
```

1. `saves/` に `.tfosave` が追加されると GitHub Actions が起動する
2. GitHub 上の仮想マシンで Python と部品を入れ、`scripts/build.py` を実行する
3. `docs/players.json`・`docs/meta.json`・`docs/data/roster_plan.json`・`docs/draft.json` が書き換わり、自動でコミットされる
4. GitHub Pages（公開元は `docs` フォルダ）が再公開される

### build.py の計算内容

| 項目 | 方法 |
| --- | --- |
| セーブ時点の総合 | 役割ごとに、過去の「能力6項目→総合」の組から重みを最適化し、単調変換（等張回帰）で合わせる |
| 予測最大・到達年齢 | 引退選手と34歳以上の選手の経歴から勾配ブースティング回帰で学習。新人は専用モデル。設定ピーク年齢を過ぎた選手は「その年以降の最高総合」モデルを使い、過去の最高値は使わない |
| 状態 | 新人／下降期／ピーク／成熟期／伸び盛り（到達年齢と設定ピーク年齢から判定） |
| 前年比 | 今の値 − 直近の開幕時の値 |
| 三軍推奨 | 一軍以外から、年齢ごとの総合の基準 → 総合80到達の見込み → 空き枠（20歳以下・総合順）の順に「全選手数−70」人 |
| 練習メニュー | 役割ごとの総合への重み × (100 − 能力値) が最大の能力 |
| 今後の最高 | 「その年以降の最高総合」を目的変数にした勾配ブースティング。設定ピーク年齢を過ぎた選手にだけ使う |
| ドラフト候補の予測最大・到達年齢 | 引退選手＋31歳以上の在籍選手で学習（1年目開幕時の総合・年齢・将来性・注目度・投手か・developmentPotential・riseRate・peakAge・growthVolatility）。候補の1年目開幕時の総合は今の総合＋2.3、年齢は翌年 |

### パソコンで手動実行したいとき

```
pip install -r requirements.txt
python scripts/build.py
```

`saves/` 内の一番新しい `.tfosave` を自動で選びます。
